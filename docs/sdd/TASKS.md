# Wearo.ai MVP atomic developer tasks

Tasks are listed in dependency order. A task is atomic enough for one owner and one reviewable change. Story points use only `1, 2, 3, 5`. Initial `BLOCKED` means a named decision is required to complete the behavior correctly.

Range shorthand in the `Original WR IDs` column means selected source IDs within those endpoints only. It never expands to a deferred ID. `TASK_DEPENDENCIES.md` provides the authoritative exact 90-row mapping.

## Status update protocol

Only one unblocked task is executed at a time after backlog approval. Before work, set that task to `IN_PROGRESS`. After implementation, run its listed tests and attach evidence; set `DONE` only when its Definition of Done is satisfied. Set `BLOCKED` only for a concrete unmet dependency/decision and record it in `IMPLEMENTATION_PLAN.md`. Do not mark a parent story or epic `DONE` until every child is done.
